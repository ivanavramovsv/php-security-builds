# PHP 8.2.35 — ARM64 отделно пакетиране (експеримент)

**Състояние: само за CI. Не инсталирай върху Oracle VPS.**

## Архитектурно решение

Преди да реконструираме точните Ubuntu 20.04 PPA `.deb` пакети на Surý, изпитваме механизма за пакетиране чрез изцяло отделен лабораторен пакет, за да не рискуваме стандартната конфигурация на HestiaCP.

- Пакетно име: `php82-arm64-sidecar-lab`.
- Лабораторна версия: `8.2.35-0lab1`.
- Целева архитектура и среда: `arm64` в изолиран контейнер Ubuntu 20.04.
- Неприпокриваща се директория: `/opt/php82-arm64-sidecar-lab/8.2.35/`.
- PHP: CLI и PHP-FPM от официалния PHP 8.2.35, с 11 вградени разширения; външен Imagick 3.7.0, компилиран със собствения `phpize`.
- Динамичните библиотеки са изведени от `dpkg-shlibdeps` на бинарните файлове, а не от предположения.
- Няма `postinst`, `preinst`, `prerm`, `postrm`, системни услуги, Apache/nginx/HestiaCP интеграция, и няма инсталационен сценарий.

## Защити в GitHub Actions

Файл: [php82-sidecar-deb-lab.yml](../.github/workflows/php82-sidecar-deb-lab.yml). Това е **build/test workflow**, не диагностичен скрипт.

Процесът проверява официалните SHA-256 на PHP и Imagick, компилира двата компонента от източник в отделна директория, проверява NTS/API и 11-те вградени разширения, изпълнява PNG roundtrip, генерира лабораторен `.deb`, проверява полетата `Package/Version/Architecture`, изричното отсъствие на maintainer scripts, проверява всички пътища във вътрешното съдържание, извлича с `dpkg-deb -x` и сравнява двоичните файлове с оригиналните компилирани файлове.

**Не публикуваме самия `.deb` пакет.** В GitHub Actions се публикува само текстов отчет. GitHub няма SSH достъп или други креденшъли до Oracle VPS. При всяка грешка процесът е FAIL.

## Важни ограничения

1. Това е само sidecar package proof. Той **не** е заместител на `php8.2-fpm`, `php8.2-cli`, `php8.2-common` и останалите Sury/Ubuntu пакети.
2. Изолираното Ubuntu 20.04 е компилационна среда, не доказателство за съвместимост на библиотеките на реалния VPS. Първият експеримент изисква `libssl1.1`, `libicu66` и ImageMagick 6 Q16 от Focal — не може да се приложи произволно към други ОС.
3. PHP-FPM има само базово конфигуриране: няма верифициран pool management, сокети, HestiaCP интеграция или всички необходими на сайт разширения.
4. Липсва надеждно възстановяване на старите Sury пакети — 0 от 7 исторически оригинални `.deb` пакета са проверено налични.
5. Не е реконструирано историческото Ubuntu PPA `debian.tar.xz` пакетиране. Тестът не отстранява този блокер.

**DEPLOYMENT_READY=NO.** Всяко истинско внедряване изисква отделен експлицитно одобрен план и пълен rollback.

## Етап 1M — контролирана възпроизводимост на пакетния архив

Целта е да разделим два вида вариации: различни времена/метаданни в .deb архива и различно съдържание на компилираните PHP/Imagick файлове. Тази проверка **не** е равнозначна на независима възпроизводима компилация.

В GitHub Actions workflow-а е въведено лабораторно фиксирано `SOURCE_DATE_EPOCH=1790000000` и `TZ=UTC`. Стойността е **фиксиран тестов вход**, не автентична дата на PHP release или проверим исторически source timestamp.

За да се елиминират времената на файловете, всички mtime стойности във временната staging директория се нормализират до една и съща стойност непосредствено преди `dpkg-deb --build`. Два отделни `.deb` архива се сглобяват от едно и също неподвижно staging дърво и трябва да бъдат идентични byte-for-byte (`cmp`). При несъвпадение CI спира.

Допълнителният текстов CI отчет съдържа SHA-256 отпечатъци на съдържанието на staging payload, `DEBIAN/control`, PHP CLI бинарния файл, `imagick.so` и .deb файла. Това позволява бъдещо сравнение между **отделни GitHub Actions компилации**.

Инвариант: успешно повторно сглобяване на пакета от един staging tree доказва само възпроизводима архивна операция при тези входове; пълната възпроизводимост изисква независимо повторно компилиране на PHP/Imagick в нова изолирана среда и съвпадение на всички binary/payload/package хешове.

Стандартът SOURCE_DATE_EPOCH е документиран в https://reproducible-builds.org/specs/source-date-epoch/ .

Продукционна готовност остава **BLOCKED** независимо от резултата на този тест.
