# Условия за безопасно внедряване и възстановяване

**Статус: BLOCKED. Няма разрешение за инсталация върху Oracle VPS.**

Цел: проверими поправени PHP 7.4, 8.0 и 8.2 пакети за Ubuntu 20.04 ARM64 / HestiaCP. Без общо обновяване на Ubuntu, пакетни зависимости, сървърно рестартиране или внедряване чрез GitHub Actions.

## Проверени исторически доказателства

- Оригинален PHP 8.2.24 пакет от 27 септември 2024 г.: Launchpad ARM64 build 29118485, точна версия 8.2.24-1+ubuntu20.04.1+deb.sury.org+1.
- Исторически build log, ARM64 buildinfo, ARM64 changes и source changes са проверени чрез SHA-256.
- Оригиналният изходен архив PHP 8.2.24 от PHP.net съвпада с Launchpad SHA-256.
- Историческите configure цели включват fpm-build, cli-build и още пет build варианта.
- Debian PHP Team историческите правила са проверим кандидат за сравнение, но не е доказана идентичност с оригиналното Ubuntu PPA пакетиране.
- От оригиналния buildinfo са извлечени 397 зависимости, а 34 от 64 избрани чувствителни зависимости се различават или липсват в чистия Focal контейнер.
- Оригиналните PPA .dsc и .debian.tar.xz са недостъпни (HTTP 404).
- Седемте проверени стари ARM64 .deb пакета не могат да се възстановят от проверените адреси: 0 от 7 SHA-256 PASS.

## Изисквания преди продукционно внедряване

1. Точно документировано и проверимо Focal Debian пакетиране с обозначени отклонения от историческия PPA оригинал.
2. Пакети със собствена версия и dependency-разрешаване, които не подменят непланирано системни компоненти.
3. Тестове на PHP API/ABI, FPM, CLI, PHP ini, HestiaCP и действително използваните разширения, включително външните модули.
4. Възпроизводима инсталационна симулация само на точно посочените пакети, без премахване на други.
5. Възможност за доказано възстановяване: оригинални бинарни пакети с проверени контролни суми или независим проверен пълен restore. Копие на /usr/lib/php само по себе си не е пакетно възстановяване.
6. Проверени резервни копия и план по една PHP версия, с проверки за приложенията след всяка стъпка.
7. Отделно изрично одобрение преди която и да е промяна върху продукционния Oracle VPS.

## За какво служат workflows

- **source-audit.yml**: исторически оригинални източници и пакетен gate.
- **repro-inspection.yml**: извличане на configure аргументи и проверка на достъпността на оригиналните ARM64 .deb.
- **upstream-smoke.yml**: минимален upstream PHP 8.2.35 CLI/FPM build, без Debian пакети.
- **expanded-php82-smoke.yml**: разширени вградени PHP модули в изолиран Focal ARM64 контейнер; не е съвместимостен сертификат за продукция.

Изградените в GitHub изпълнителите файлове не се публикуват като инсталационни пакети. Няма SSH, пароли, Oracle ключове или автоматично внедряване.

Текущата временна настройка session.upload_progress.enabled=0 не замества действителните PHP поправки.

Изследването на пълно Ubuntu надграждане и Oracle Always Free последствията остава отделна операция.
